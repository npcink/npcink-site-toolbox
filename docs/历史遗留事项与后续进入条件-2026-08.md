## 一、目的与口径

本文汇总此前用户体验排查、Alt 写入冲突、搜索统计限流、后台/PHP 国际化、Docker 发布验收、对象存储、兼容性和 AI 诊断讨论中的当前结论，作为下一阶段排期入口。

状态按以下口径判断：

- **已完成**：已有代码、自动化测试、真实环境或精确发布包证据。
- **待实施**：目标明确，但仍缺实现或可交付产物。
- **待真实验证**：代码和自动化已具备，仍缺外部环境、凭据或真实业务样本。
- **已关闭**：经产品边界或冲突分析决定不再实现，不应重新当作遗漏。
- **候选提案**：尚未满足准入条件，不进入当前版本承诺。

历史台账中的阶段性“尚未完成”不得覆盖本文的当前状态。阶段总览和关键经验见[3.3.0 阶段收尾总结与后续路线图](3.3.0-阶段收尾总结与后续路线图-2026-08.md)，详细时间线和原始证据仍保留在[开发收尾与质量治理手册](开发收尾与质量治理手册-2026-08.md)。

## 三、仍待处理的事项

### P1：OSS 三家真实供应商端到端验证

**当前状态**：待真实验证。

当前自动化已经覆盖请求构造、签名固定向量、权限边界、失败回退和本地副本策略，但尚未使用真实阿里云 OSS、腾讯云 COS、七牛云 Kodo 凭据证明供应商端行为。

**未完成原因**：

- 缺少三家供应商的真实测试凭据；
- 缺少允许写入并可完整清理的测试 Bucket；
- 不能在未经授权的生产 Bucket 中执行写入测试；
- 本地模拟不能替代跨地域网络、供应商权限和公开读取验证。

**重新进入条件**：

1. 为目标供应商准备最小权限、可撤回的测试凭据；
2. 明确测试 Bucket、目录前缀、公开读取策略和清理责任；
3. 备份当前插件配置，记录回滚方法；
4. 获得执行远端写入和删除测试对象的明确授权。

**完成标准**：

- “测试连接”固定对象真实写入成功；
- 目录前缀、Endpoint 和公开 URL 与预览一致；
- 上传一张测试图片，原图及派生尺寸全部成功后才切换远端状态；
- 任一文件失败时保持 Local 真相；
- 测试对象和凭据完成清理并保留脱敏证据。

### 已完成：English (United States) 正式语言包

**当前状态**：已完成。

仓库现已随发布包提供 `npcink-site-toolbox-en_US.po`、`.mo`、Admin JavaScript JSON 和维护倒计时 JSON。此前“只有 POT、英文回退中文”的描述属于历史时点，不再代表当前状态。

**交付与审校方式**：

- 使用本地模型生成初稿，不采用质量失败的 Argos 产物；
- 保护并全量验证 printf 占位符、HTML 标签和 WordPress JSON 路径；
- 对导航、保存、OSS、备案、数据库、媒体/WebP、评论、AI、隐私和动态格式串实施术语审校与 152 项定向校正；
- `msgfmt`、`msgcmp`、PHPUnit、PHPStan、Admin 测试与生产构建全部通过。

**最终证据**：

- 最终 ZIP：234 entries、1,262,350 bytes、SHA-256 `92f4dedd6eeeb1120ca36af765bbfceb86ab83a5428199541b9349f603f9ccf3`；
- WordPress 7.0.4 / PHP 8.2.32 / locale `en_US` 中 PHP `设置` 返回 `Settings`；
- Admin 导航、保存和对象存储界面显示英文，无控制台错误；
- Plugin Check 2.0.0：0 errors / 2 accepted core-hook warnings。

新增其他 locale 属于新的独立工作包，不再作为本次 `en_US` 交付遗漏。

### P2：第三方主题与页面构建器兼容性窄测

**当前状态**：待真实验证。

当前已覆盖核心 WordPress 路径、核心区块主题和项目现有主题，但不能据此宣称兼容全部第三方主题和页面构建器。

**未完成原因**：

- 主题、构建器和版本组合空间过大；
- 无法通过一次全量穷举得到长期有效的兼容结论；
- 必须先根据真实用户环境确定代表组合。

**重新进入条件**：

1. 从真实站点或目标用户中选择 2–3 个代表组合；
2. 固定 WordPress、PHP、主题和构建器版本；
3. 明确只读冒烟和允许写入的测试动作；
4. 为前台样式、编辑器、评论过滤和动态区块建立窄测试清单。

**完成标准**：

- 插件后台导航、设置保存和维护工具无冲突；
- 前台动态区块、评论路径、维护页和插件 CSS 不破坏主题布局；
- 编辑器无致命错误和控制台错误；
- 每个组合都记录版本、结果、已知限制和清理情况。

### P2：AI 诊断真实价值案例

**当前状态**：待真实验证。

当前已有白名单事实、权限、脱敏、追问次数、失败降级和受控评测证据，但缺少真实业务故障证明诊断结果确实有用。

**未完成原因**：

- 当前样本主要来自受控环境和构造问题；
- 没有至少 3 个可脱敏、可复验的真实故障事件；
- 诊断回答“看起来合理”不能替代问题修复后的事实复验。

**重新进入条件**：

1. 收集得到授权的真实问题，并完成脱敏；
2. 为每个问题记录原始事实、诊断建议、人工决策和修复结果；
3. 不扩大 AI 权限，不允许自动执行建议或持久化对话上下文。

**完成标准**：

- 至少 3 个不同类型的真实案例；
- 建议与白名单事实一致，没有虚构设置或凭据；
- 至少包含一次成功修复复验和一次无法诊断时的安全降级；
- 形成可复用的匿名案例和反例。

### P2：WordPress.org 正式提交或重新提交

**当前状态**：本地发布门禁已完成，外部发布流程暂无完成证据。

**未完成原因**：

- 精确 ZIP 和 Plugin Check 通过不等于目录团队已经审核通过；
- 正式上传、邮件回复、slug 分配和 SVN 发布属于需要账号和人工确认的外部操作；
- 未经明确授权不应代表用户向 WordPress.org 提交或发布。

**重新进入条件**：

1. 确认 WordPress.org 账号、目标 slug 和当前审核状态；
2. 明确是首次提交、原线程重新上传，还是获批后的 SVN 发布；
3. 使用目标提交重新构建唯一 ZIP，并再次运行最新版官方 Plugin Check；
4. 获得执行外部提交的明确授权。

**完成标准**：

- 记录实际上传 ZIP 的 SHA-256；
- 保存 WordPress.org 审核结果和剩余要求；
- 获批后以同一提交同步 SVN `trunk`、版本 tag 和公开资产；
- 不将本地通过状态表述为官方目录已发布。

### P3：进一步产品体验增强

**当前状态**：候选工作包，不属于 3.3.0 发布阻塞问题。

历史讨论中还包括搜索体验增强、分类 SEO、传统 Widget 和更多主题适配。这些能力已有部分实现或基础表面，但尚未形成下一阶段的具体问题定义和验收范围。

**未立即实施原因**：

- 与本轮国际化、限流和发布收尾不属于同一个模块；
- 如果同时扩展多个功能，会重新扩大回归面并使发布证据失效；
- 应先根据真实用户反馈确定主攻项，而不是按历史关键词机械增加功能。

进入实施前必须为每一项单独建立问题描述、用户影响、非目标、公共契约、验证环境和回滚方案。

## 四、已关闭或不属于本仓库的事项

### Alt 自动写入

不再恢复为插件能力。缺失 Alt 继续由 SEO 检查和媒体体检报告，实际写入交给 WordPress 媒体库、内容人员或站点已有 SEO/媒体插件。只有未来出现明确、无冲突的所有权契约时，才允许重新提出设计评审。

### 自定义用户角色

保留为候选提案，不进入当前版本。它涉及内置角色保护、最后管理员保护、用户迁移、多站点和卸载所有权；缺少真实使用场景时不扩大权限管理责任。详情见[自定义用户角色候选功能提案](自定义用户角色候选功能提案-2026-08.md)。

### 云端控制面与治理型 AI 写入

AI 写入、提案批准、Provider Runtime、计费、队列、跨仓库工作流真相和云端控制面不属于 Npcink Site Toolbox。需要这些能力时应通过既有仓库边界和公共合同实现，不能在本插件复制一套运行时。

## 五、后续建议顺序

后续重新开工时建议按以下顺序，每次只处理一个独立工作包：

1. **OSS 单供应商真实验证**：先选择实际要用的一家供应商建立可撤回测试基线，不同时铺开三家。
2. **代表性兼容窄测**：依据真实用户环境选择主题/构建器，而不是追求全生态声明。
3. **AI 真实案例**：随真实故障积累逐案验收，不为凑数量制造样本。
4. **WordPress.org 外部发布**：在目标提交和精确 ZIP 完全稳定后执行。
5. **其他 locale 或体验增强**：按真实用户需求决定是否扩展语言，并重新排序搜索、分类 SEO、Widget 等候选项。

## 六、台账更新规则

- 本文只记录当前事实、进入条件和完成标准，不作为“已经授权执行”的依据。
- 开始某项工作前重新确认凭据、外部写入、数据清理和发布权限。
- 完成后必须补充实际版本、命令、结果、失败项、清理情况和提交 SHA。
- 发布包内容发生变化后，旧 ZIP 哈希、安装结果和 Plugin Check 结论立即失效。
- 某项被产品边界关闭后，除非所有权或真实需求发生变化，不应反复重新实现。

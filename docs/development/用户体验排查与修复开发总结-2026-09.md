## 3. 沉淀的可复用模式

1. **语言漂移测试门禁**：`bin/export-i18n-metadata.php` 的输出流 + PHP/JS 源码字面量扫描 + en_US.po 解析，全部收进 PHPUnit（`I18nCatalogCoverageTest`）。此前 `composer i18n:build` 的未翻译检查只在本地执行，隐私披露文案曾静默漂移数月；该测试上线当天即拦住本轮新增的 63 条文案。
2. **`configEpoch` 表单同步**：Context 增加单调递增计数器，`loadSettings` 成功后自增，各视图组件以它为依赖把服务端（可能已自动修正）的值写回本地表单，消除「幽灵待保存」与旧值回写。新增视图组件时沿用同一注入块即可。
3. **限流取真实 IP**：`Npcink_Toolbox_Helpers::get_rate_limit_ip()` 统一实现「REMOTE_ADDR 命中登录安全信任代理清单 → 自右向左解析 X-Forwarded-For」。新增加流量的功能一律用它，不要再取裸 `REMOTE_ADDR`。
4. **隐藏类内容权限**：查询级排除（`pre_get_posts` + `category__not_in`/`tag__not_in`/`post__not_in`）为主，正文替换只作兜底；这样归档/搜索/Feed 不泄漏标题摘要，对登录盲的页面缓存也更友好。
5. **渲染路径零远程请求、零写库**：外部票据类（微信 JSSDK）一律后台 Cron 刷新、渲染期只读缓存；派生数据（特色图）在写时（`save_post`）固化，不在读时（`the_post`）计算。

## 4. 关键教训

### 4.1 子代理/二手结论必须回核心源码验证

排查代理断言「`admin_enqueue_scripts` 在页面/自定义类型列表收到 `edit.php?post_type=…`，因此按钮不会出现」。对照 WP 核心 `wp-admin/admin.php` 的 `$hook_suffix` 赋值链（核心页无 plugin_page 时即 `$pagenow`）与官方文档确认：所有文章类型列表页的后缀统一是 `edit.php`，`?post_type=` 形态只出现在插件自注册页面。据此纠正了两条误报，也反向确认了新模块的判定写法正确。**任何关于 WordPress 运行时行为的结论，以核心源码/官方文档为准，不采信推断。**

### 4.2 「静默失效」是工具箱插件最伤信任的缺陷类别

本轮修复的三类静默失效——首页 SEO 字段保存但永不输出（Schema 缺激活键）、关键词内链正则恒失败（分隔符非法）、模糊图「登录可见」标签从未显示（`::before` 挂在替换元素上）——共同点是功能开关正常、设置能保存、没有任何报错。防范方式：新功能的验收必须包含「输出端到端可见」这一步；配置字段与激活键同 Schema 声明，避免字段存在而模块不可达。

### 4.3 批量脚本改动必须先在小范围试运行

本轮两次注入脚本因模板转义（`{{}}`、双括号）批量产出语法错误，靠 typecheck 兜住。此后批量改源码一律：先改 1 个文件 → `php -l`/`tsc` 验证 → 再批量 → 再全量验证。

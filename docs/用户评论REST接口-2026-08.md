# 用户评论 REST 接口

> 日期：2026-08-06
>
> 状态：实现合同
>
> 命名空间：`npcink-site-toolbox/v1`

## 认证与权限

- 管理员必须先在“Npcink 站点工具箱 → 内容与页面 → 评论”中开启“用户评论 REST 接口”；默认关闭；
- REST 总开关关闭时，不注册“我的评论”菜单，也不注册本文接口；
- “显示‘我的评论’后台页面”是独立的兜底界面开关；关闭它不会关闭 REST 接口；
- WordPress 后台页面使用登录 Cookie 与 `X-WP-Nonce`；
- 外部客户端使用 WordPress 原生应用程序密码和 HTTPS Basic Auth；
- 服务端始终使用当前认证用户 ID 判断评论归属；
- 不接受客户端提供 `user_id`，也不通过姓名或邮箱判断归属；
- 应用程序密码创建后只显示一次，插件不读取、保存或回显明文。

## 获取应用程序密码

1. 使用需要管理评论的 WordPress 用户登录；
2. 打开“用户 → 个人资料”；
3. 找到“应用程序密码”，填写客户端名称，例如“Npcink 评论客户端”；
4. 点击“添加新的应用程序密码”；
5. 立即复制生成的密码。离开页面后不能再次读取，只能撤销后重新创建；
6. 外部客户端必须通过 HTTPS 使用用户名和应用程序密码进行 Basic Auth。

建议每个客户端单独创建密码，停用客户端时在个人资料页撤销对应密码。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/me/comments` | 分页读取当前用户评论 |
| `POST` | `/me/comments` | 发表顶级评论 |
| `PATCH` | `/me/comments/{id}` | 修改无有效回复的当前用户评论 |
| `DELETE` | `/me/comments/{id}` | 将无有效回复的当前用户评论移入回收站 |
| `POST` | `/me/comments/batch-delete` | 每批最多将 20 条评论移入回收站 |

列表支持 `page`、`pageSize` 和 `status=all|approved|pending|trash`。响应使用 `data + pagination`。评论对象只返回评论 ID、文章信息、正文、状态、日期、并发校验哈希和可操作状态，不返回邮箱、IP 或应用程序密码。

## curl 使用示例

先设置站点、用户名和刚创建的应用程序密码：

```bash
API_BASE='https://example.com/wp-json/npcink-site-toolbox/v1'
WP_USER='your-login-name'
APP_PASSWORD='xxxx xxxx xxxx xxxx xxxx xxxx'
```

正式环境必须将 `API_BASE` 设为 HTTPS 地址。在 Local、WordPress Playground 等隔离的本地开发环境中，可以使用 HTTP 做联调，但这不是生产环境的安全配置。

读取自己的评论：

```bash
curl --user "$WP_USER:$APP_PASSWORD" \
  "$API_BASE/me/comments?page=1&pageSize=20&status=all"
```

发表评论：

```bash
curl --user "$WP_USER:$APP_PASSWORD" \
  --header 'Content-Type: application/json' \
  --request POST \
  --data '{"postId":123,"content":"这是一条评论"}' \
  "$API_BASE/me/comments"
```

成功时返回 HTTP `201` 和完整评论对象：

```json
{
  "id": 456,
  "postId": 123,
  "postTitle": "示例文章",
  "postUrl": "https://example.com/example-post/",
  "content": "这是一条评论",
  "status": "approved",
  "date": "2026-08-06T08:00:00",
  "expectedHash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "hasReplies": false,
  "canEdit": true,
  "canDelete": true
}
```

修改评论时，`expectedHash` 必须来自最近一次列表或详情响应：

```bash
curl --user "$WP_USER:$APP_PASSWORD" \
  --header 'Content-Type: application/json' \
  --request PATCH \
  --data '{"content":"修改后的评论","expectedHash":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}' \
  "$API_BASE/me/comments/456"
```

成功时返回 HTTP `200` 和更新后的评论对象：

```json
{
  "id": 456,
  "postId": 123,
  "postTitle": "示例文章",
  "postUrl": "https://example.com/example-post/",
  "content": "修改后的评论",
  "status": "pending",
  "date": "2026-08-06T08:00:00",
  "expectedHash": "abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789",
  "hasReplies": false,
  "canEdit": true,
  "canDelete": true
}
```

`expectedHash` 会随评论内容变化，后续修改必须使用这个新哈希。

删除单条评论：

```bash
curl --user "$WP_USER:$APP_PASSWORD" \
  --request DELETE \
  "$API_BASE/me/comments/456"
```

首次删除成功返回 HTTP `200`：

```json
{"id":456,"status":"deleted"}
```

对已在回收站的评论重复请求删除时，仍返回 HTTP `200`：

```json
{"id":456,"status":"alreadyDeleted"}
```

批量删除评论，每次最多 20 条：

```bash
curl --user "$WP_USER:$APP_PASSWORD" \
  --header 'Content-Type: application/json' \
  --request POST \
  --data '{"commentIds":[456,457,458]}' \
  "$API_BASE/me/comments/batch-delete"
```

成功响应返回 HTTP `200`，并分别报告每个评论的处理结果：

```json
{
  "summary": {
    "requested": 3,
    "deleted": 3,
    "failed": 0
  },
  "results": [
    {"id": 456, "status": "deleted"},
    {"id": 457, "status": "deleted"},
    {"id": 458, "status": "alreadyDeleted"}
  ]
}
```

`summary.deleted` 表示成功处理的数量，包含状态为 `alreadyDeleted` 的幂等结果。

WordPress 应用程序密码中的空格仅用于方便阅读；curl 可以直接使用带空格的完整密码。认证失败返回 `401`，功能未开启时路由不存在并返回 `404`。

## 修改合同

修改请求必须同时提交 `content` 和最近一次读取到的 `expectedHash`。哈希不一致时返回 `409`，客户端应刷新后重新确认。修改成功后评论进入待审核状态。

## 删除合同

- 删除只调用 WordPress 回收站能力，不永久删除数据库记录；
- 已有有效回复时返回 `409`；
- 不属于当前用户或不存在的评论统一返回 `404`；
- 已在回收站的评论作为幂等结果返回 `alreadyDeleted`；
- 批量删除逐条处理并返回成功、失败数量及逐条结果，不承诺数据库事务。
